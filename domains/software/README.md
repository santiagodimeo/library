# Software

How software systems are built, run, and fail. Notes hold mechanisms and
tradeoffs, not tutorials.

| Area | Holds | Go-to sources |
|---|---|---|
| `distributed-systems` | Consensus, replication, consistency models, time, partitions | USENIX, ACM, Jepsen, DDIA |
| `architecture` | Service boundaries, integration and messaging patterns, evolutionary design | Martin Fowler, DesignGurus, ACM Queue |
| `data` | Storage engines, indexing, transactions, streaming, CDC | VLDB, SIGMOD, CIDR |
| `reliability` | SLOs, overload, retries, incident practice, observability | Google SRE, AWS Builders' Library, Brendan Gregg |
| `security` | Threat models, authn/authz, cryptographic practice | NIST, OWASP, USENIX Security, IETF |
| `languages-runtimes` | Type systems, memory management, concurrency models, compilers | PLDI, OOPSLA, ACM |
| `ai-systems` | LLM architecture, training and inference systems, evaluation, agents | arXiv → published venue, NeurIPS/ICML via ACM/PMLR |
| `algorithms` | Data structures and algorithms with real cost profiles | ACM, CLRS, Skiena |
